- (decision) Module 1 (short-term SYS forecast, MVP focus): produces fundamental Nordic system price forecast WITH weather outcome space across the ECMWF (EC) 15-day forecast ensemble — i.e. output is a distribution across weather ensemble members, not a single point forecast. Compared against financial derivatives short-term contracts (daily/weekly, up to 2 weeks forward).
- (decision) Module 1 methodology is explicitly top-down (start from a realised historical bid curve, adjust for fundamentals change) vs. the bottom-up approach used by most commercial forecasts — this is the stated core differentiator, named explicitly as experimental.
- (decision) Module 1 data sources are now concrete: historical bid curves from Nord Pool API; fundamentals data from Volue API.
- (decision) Module 1 scope is explicitly MVP-only due to time constraints: goal is to determine whether the top-down approach is worth further developing into an operative forecast, not to ship an operative forecast itself.
- (decision) Module 1 supply-curve adjustment factors: seasonality (day-of-week, public holiday), hour-in-day pattern matching to reference state, wind production, PV production, unregulated hydro production, balancing capacity market changes (CM up/down effect on must-run vs marginal-cost bidding and availability), revision/UMM availability (all technologies incl. nuclear), nuclear bidding behaviour within available capacity, CHP must-run, water value changes (regression/sensitivity-based), thermal SRMCs beyond nuclear (gas, coal, biomass, CHP marginal cost bidding).
- (decision) Module 1 demand-curve adjustment factors: seasonality (day-of-week, public holiday, hour-in-day pattern matching), temperature-related consumption (need to locate where in curve bids respond to temperature), revision/UMM availability of large consumers. Net export flows adjusted via external vendor flow data.
- (decision) Module 1 calibration approach: start with assumed change-models per factor, fit against actual observed supply/demand curve changes, test/diagnose/calibrate/improve in-sample, then attempt out-of-sample forecasting once in-sample fit is acceptable.
- (decision) Module 1 frontend (not detailed yet): interactive figures of curves and cleared prices showing weather outcome space per time step; high user configurability (choice of reference state, choice of weather forecast input if vendor API supports it).
- (decision) Module 1 later-phase (explicitly beyond initial project scope): Nordic bid identification/disaggregation, extend to CWE and Baltic areas, full area-level clearing.
- (decision) Module 2 (mid-term/forward model) reframed: rolling statistical model over recent history with user-configurable history length, explanatory variables, and a recency decay weight parameter. Explains SYS forward price CHANGE for tradable contracts starting at W+3 through months/quarters/CALs (previously stated as DEC/Q4/CAL only).
- (decision) Module 2 purpose is twofold: (1) output sensitivities usable out-of-sample to compute expected price moves as new info arrives intraday (or longer, per baseline), compared live against actual market moves; (2) visualise how each coefficient evolves over time per contract.
- (decision) Module 2 later-phase (beyond initial scope): use live coefficients to adjust computationally-heavy vendor fundamental models in real time as new info arrives (those models aren't rerun continuously); compare the real-time-adjusted fundamental forecast against the live financial market to flag mispricing.
- (decision) Module 3 (NEW vs. prior brief, replaces the 'news synthesizer' idea): Grid & availability module — Nordic geographic map of transmission network elements and production assets, availability shown on a scrub-able timeline. Purpose: understand grid bottlenecks relevant to area-level Nordic pricing. Includes an AI-powered assistant to answer user questions on grid bottlenecks and Flow-Based Market Coupling (FBMC).
- (decision) Module 3 later-phase (beyond initial scope): historical shadow-price analysis tools, tools to relate FB variables to fundamental variables (user already has substantial code for this from work); AI assistant extended to reason over historical shadow prices, FB variables, and forward-looking grid availability.
